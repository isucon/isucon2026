### 構成
- isu01（asia）: Go アプリ1プロセスで全リージョンを処理。:80 で asia、:8081 で europe、:8082 で america を受ける（リージョンはポートで決まる）。nginx は停止・無効化。:8090 で sigworker から署名表を受け取る。pprof とルート統計は 127.0.0.1:6060。
- isu02/isu03: nginx が /api/ を isu01:8081/:8082 へ転送し、静的ファイルはローカルで返す。isureal-go と guard は停止・無効化。sigworker（初期画像の署名を事前計算）が稼働。
- isu04: PostgreSQL（設定は conf.d/isucon.conf。リポジトリの conf/postgresql-isucon.conf にも置いた）。外部キーはすべて削除し、インデックスを追加・一部削除。
- isu01 の /home/isucon/imgcache: 初期画像180万枚のディスクキャッシュ（約15GB。DB が正のデータ）。

### 注意点
- 13:2x ごろ、isu04 の /etc/postgresql/16/main/conf.d/isucon.conf（既存ファイル）を中身を確認せずに上書きした。DB に接続できなくなったので listen_addresses='*' を追加して復旧した。元のファイルに他の設定があったかどうかは分からない。
- 画像 URL の exp は10分単位で切り下げている（有効期間は 23h50m〜24h）。ベンチからの指摘はない。
- 署名の高速化で crypto/internal の関数を go:linkname で呼んでいるため、ビルドには -ldflags=-checklinkname=0 が必要（Makefile に記載）。
- init.sh から indexes.sql の実行を外した（ALTER TABLE が長いクエリにブロックされて initialize が詰まったため）。スキーマの変更は DB に適用済み。
- ソースは ~/webapp の git で管理している。補助スクリプトは ~/bench_run.sh（ベンチ実行と結果取得）、~/prebench.sh、~/analyze.sh、~/timeline.py。
