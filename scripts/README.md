# 企業賞の判定

`check-award` は [当日マニュアルの企業賞](../docs/manual.md#企業賞)13種類を判定します。
Goの標準ライブラリだけで動作し、DB接続やポータルの起動は不要です。
`./scripts/check-award` はGoコードを一時ディレクトリへビルドして実行するため、Goのインストールが必要です。
一時ディレクトリは実行終了時に削除します。
入力JSONは同梱の `export-award.sql` でポータルDBから作成できます（後述）。

```sh
./scripts/check-award results.json
./scripts/check-award --json results.json > awards.json
cat results.json | ./scripts/check-award -
go test scripts/check-award.go scripts/check-award_test.go
go vet scripts/check-award.go
# バイナリを直接利用する場合
go build -o /tmp/check-award scripts/check-award.go
```

## 入力

次は形式を示す架空のデータです。
日時には実際の競技日とタイムゾーンを指定してください。

```json
{
  "contest_started_at": "2026-10-31T10:00:00+09:00",
  "scoreboard_closed_at": "2026-10-31T17:00:00+09:00",
  "contest_ended_at": "2026-10-31T18:00:00+09:00",
  "teams": [
    {
      "id": 1,
      "name": "サンプルチーム",
      "member_count": 3,
      "final_rank": 1,
      "disqualified": false,
      "runs": [
        {"enqueued_at": "2026-10-31T10:29:00+09:00", "at": "2026-10-31T10:30:00+09:00", "score": 2000, "passed": true},
        {"enqueued_at": "2026-10-31T16:59:59+09:00", "at": "2026-10-31T17:05:00+09:00", "score": 10000, "passed": true},
        {"enqueued_at": "2026-10-31T17:29:00+09:00", "at": "2026-10-31T17:30:00+09:00", "score": 20260, "passed": true}
      ]
    }
  ]
}
```

- `id`：重複しない正の整数。
- `name`：空でないチーム名。
- `member_count`：正の整数の登録メンバー数。
- `final_rank`：運営が確定した最終順位。受賞対象チーム間で重複しない正の整数を指定します。順位の再計算はしません。対象外チームでは省略できます。
- `disqualified`：追試などによる失格を表す真偽値。
- `runs`：実行済みベンチマークの全履歴。追試、キャンセル済みジョブ、未実行ジョブは含めません。
- `enqueued_at`：Enqueue時刻。必須で、`at` 以下の時刻を指定します。激流賞の基準点を選ぶ際に使います。
- `at`：結果の計測時刻。全チームで同じ時刻基準を使用します。同一チーム内の同時刻は入力エラーとします。
- `score`：非負の64ビット符号付き整数（最大9,223,372,036,854,775,807）。`passed: false` の走行は入力値にかかわらず0点として扱います。
- `passed`：成功を表す真偽値。

競技開始時刻以上、終了時刻未満の履歴を時刻順に並べて判定します。
最後の走行がFAIL、競技中の履歴がない、または失格のチームはすべての賞から除外します。
最終スコアには最後の走行の値を使用します。
最終順位は入力を信頼するため、最高点ベースの競技中ランキングをそのまま転用しないでください。

## 判定方法

マニュアルと公開Clar 40、41、46、107に基づいて判定します。
Clarの内容は [PRレビュー](https://github.com/isucon/isucon2026/pull/368#pullrequestreview-5722023363) に記録されています。
これらで数式や境界条件が明記されていない箇所は、以下の解釈を採用しています。
運営の確定ルールと一致することを確認してから表彰に使用してください。

| 賞のID | 判定方法 |
| --- | --- |
| `hatena` | 最終スコアから、16:59台まで（`enqueued_at < scoreboard_closed_at`）にEnqueueされた0点ではない最後の走行のスコアを引いた値が大きい上位3チーム。結果の計測が17:00以降でも、Enqueueが17:00より前なら基準点の候補です。Enqueue時刻が最後の走行を採用し、同一Enqueue時刻なら計測時刻が後の走行を採用します。0点（FAILを含む）は飛ばします。17:00ちょうどのEnqueueは候補に含めません。該当する走行なし、増加量0以下は対象外です。 |
| `layerx` | 最終スコア÷登録メンバー数が最大の1チーム。 |
| `m3` | 最終順位が3位、33位、333位のチーム。 |
| `lineyahoo` | 最終スコア÷最初の非0点の走行のスコアと10との差の絶対値が最小の1チーム。0点とFAILを飛ばします。非0点の走行がない場合は対象外として警告します（Clar 41）。 |
| `kokorozashi` | 最終スコアと55,634との差の絶対値が最小の1チーム。同点は最終順位が上のチームを採用します（Clar 107）。 |
| `forcia` | 最終順位が25位のチーム。 |
| `kauche` | 最終スコアの8の個数、順位の8の個数が多い順、最終順位が上位の順で1チーム。8の個数を合算しません。 |
| `enechain` | 0点とFAILを飛ばした非0点の履歴で、直前の非0点スコアからの増加量が最も大きい1チーム。非0点の履歴が1件以下、増加量0以下は対象外です（Clar 41、46）。 |
| `freee` | 最終スコアの10進表記に出現回数がちょうど3個の数字があるチームの上位3チーム。数字の連続は不要です。 |
| `splunk` | 最終順位が110位のチーム。 |
| `algoartis` | 最終スコアの16進表記でAが最多のチームだけを抽出し、最終順位順に最大3チーム。全チーム0個の場合も最多として扱います。 |
| `cyberagent` | 最終順位が202位のチーム。 |
| `kakehashi` | 最終スコアと20,260との差の絶対値が小さい順、実行回数が少ない順で1チーム。回数には競技時間内のFAILも含めます。 |

比率の比較には有理数を使い、浮動小数点の丸め誤差を避けています。
複数の賞の重複受賞は許可します。

## 出力

標準出力には賞ごとの表を出力します。
`STATUS` は `WIN`（受賞）、`TIE`（同点候補）、`NEAR`（前後または次点）です。
`RANK`、`SCORE`、`ID`、`VALUE`、`TEAM` は最終順位、最終スコア、チームID、判定値、チーム名を表します。
順位指定の賞では受賞チームだけを表示します。
判定値の比率は丸めず分数で表示します。
同点の要確認表示、未充足枠、除外理由、警告も出力します。
入力エラーは標準エラーに出力します。
終了コードは正常時0、入力エラー時2です。
要確認の同点があっても出力に成功すれば0です。

`--json` を付けるとJSON形式を出力します。
JSONの `awards` は賞ごとの以下の情報を含みます。

- `id`、`name`：賞のIDと名称。
- `winners`：条件から決まる受賞チーム。
- `near_misses`：受賞に届かなかった近い候補。選び方は後述します。
- `tied_candidates`：受賞枠の境界で同点となり、マニュアルに決着方法がない候補。
- `needs_review`：同点候補の選定が必要かどうか。
- `unfilled_places`：受賞枠数から確定した受賞チーム数を引いた数。候補不足でも正になります。

チームにはID、名前、最終順位、最終スコア、比較値 `metric` を出力します。
`metric` は左から順に昇順比較する値の文字列表現です。
最大値を選ぶ賞では負数にし、比率は必要に応じて `分子/分母` 形式にします。
順位指定賞、freee賞では抽出後の順位を表示します。
ALGO ARTIS賞ではAの個数の負数と最終順位を表示します。

たとえば3枠に対して増加量が100、90、80、80の4チームがいる場合、先頭2チームを `winners`、残り2チームを `tied_candidates` に出力します。
チームIDや入力順で同点を決着させることはありません。

`excluded_teams` は全賞からの除外理由、`warnings` は非0点の履歴不足、クローズ前にEnqueueされた非0点の履歴不足、入力順位の矛盾による個別の賞からの除外を示します。

## 前後の候補と出力例

`near_misses` には、受賞者と未確定の同点候補を除いた次点3チームを、各賞の比較順で出力します。
3番目と同じ比較値のチームがいる場合は全員を含めます。
M3賞、フォルシア賞、Splunk賞、0xCA賞は順位指定のため、次点は出力しません（JSONの `near_misses` は空配列です）。
ALGO ARTIS賞はAの個数が少ないチームも次点に含めます。
freee賞は出現回数がちょうど3個の数字があるチームから次点を選びます。
非0点の履歴不足などで比較できないチーム、FAILや失格で受賞対象外のチームは含めません。
候補がなければ空配列です。

架空の19チームを含む入力例を用意しています。
順位は確定順位の抜粋で、実際の参加チームや競技結果ではありません。

```sh
./scripts/check-award scripts/testdata/check-award-example.json
```

たとえばフォルシア賞は25位の受賞チームだけを表示します。
ココロザシ賞は55,634点のチームを `winners`、55,635点、55,633点、60,000点のチームを `near_misses` に出力します。

入力例のSample Team 1は15:00 Enqueueの80,000点の後、16:59:59にEnqueueし、17:05に計測された50,000点を激流賞の基準点として使います。
最終スコア100,000点との差は50,000点です。

## ポータルDBからの入力作成

読み取り権限のある接続先を `PGSERVICE` または通常の `PGHOST`、`PGDATABASE` などで設定します。
パスワードは `.pgpass` などで管理し、コマンドや出力JSONに含めません。
競技日の日時は実際の設定に合わせて指定してください。

```sh
psql -XqAt -v ON_ERROR_STOP=1 \
  -v contest_start='2026-10-31T10:00:00+09:00' \
  -v scoreboard_close='2026-10-31T17:00:00+09:00' \
  -v contest_end='2026-10-31T18:00:00+09:00' \
  -f scripts/export-award.sql > /tmp/award-input.json
./scripts/check-award /tmp/award-input.json
```

SQLは単一のSELECTで、DBのデータを変更しません。
次の対応で抽出します。

| 入力 | ポータルの列または計算 |
| --- | --- |
| `enqueued_at` | `benchmark_jobs.created_at` |
| `at` | `benchmark_results.marked_at` |
| `score` | `benchmark_results.score`。`passed = false` は0点に補正 |
| `passed` | `benchmark_results.passed`。NULLはポータルと同様にFAIL扱いしない |
| `member_count` | チームごとの `contestants` の件数 |
| `final_rank` | 最終走行がFAILのチームを除き、最終スコア降順、最終 `marked_at` 昇順 |

`teams.disqualified`、`withdrawn`、`is_hidden` のチームは抽出しません。
走行は `finished AND exit_status = 0 AND exit_signal IS NULL` を満たす結果に限定し、追試の `post_validation` ジョブを除きます。
時刻は `contest_start <= marked_at < contest_end` で絞ります。
最終スコアと最終計測時刻まで一致した場合はチームID昇順で順位を固定します。
ポータルで別の順位が確定している場合は、確定順位を入力してください。
最後の走行がFAILのチームと履歴のないチームもJSONには残し、判定側で受賞対象から除外します。

カケハシ賞の実行回数は、この抽出後の履歴件数です。
正常終了したベンチマーカーが返したFAILは数えますが、プロセスの異常終了、シグナル終了、未完了、追試は数えません。
登録メンバー数が0、Enqueue時刻が計測時刻より後などの不整合は判定時に入力エラーになります。

手作業で入力する場合は、`final_rank` が最終スコア降順、同点時の最終計測時刻昇順と矛盾すると警告します。
部分的なチーム一覧も許容するため、順位の欠番は警告しません。
警告が出ても順位を自動で書き換えることはありません。

SQLの結合テストは、一時テーブルを作成できる検証用PostgreSQLで実行します。
本番DBをテスト接続先に指定しないでください。

```sh
CHECK_AWARD_TEST_DATABASE_URL='postgresql://localhost/award_test' \
  go test scripts/check-award.go scripts/check-award_test.go -run TestPortalExport -v
```

ココロザシ賞以外の未規定の同点は、引き続き候補として表示します。
freee賞は「ちょうど3個」で判定します。たとえば111、91919、1000は対象、1111、8888、100000は対象外です。
別の数字が4個以上あっても、ちょうど3個の数字があれば対象です（例：1111222）。
全賞への順位優先ルールの拡張は運営の確定判断を要します。
