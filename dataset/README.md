# dataset — ISUReal の初期データ

ISUReal の初期データを、乱数の種から決定的に作る Go モジュールです。

- `webapp/datagen` が、これを `webapp/sql/002-seed.sql` に書き出します。
- `bench` は同じ設定からデータを再計算し、既存ユーザーとしてのログインや履歴の検証に使います。
  そのため、ユーザーのシークレットキーも、行の ID も、画像の中身も、seed と一致します。

データは 2 つに分けて作ります。

- **関係**（ユーザー、友達関係、申請、フォロー、ブロック、投稿期間）は小さいので、`Generate` で
  一度に作ってメモリに持ちます。乱数は用途ごとに別の列を使い、ID は 1 本の列から順に振ります。
- **履歴**（投稿と、それに付く RealMoji とコメント、通知）は大きいので、`PostOn` で
  「ユーザー × 日」ごとにその場で作ります。乱数の列と ID は seed、日、ユーザーの番号から決まり、
  ほかの日やユーザーの生成を経ずに作れます。datagen は日ごとに作っては書き、bench は確かめる
  ユーザーの確かめる月の分だけを作り直すので、どちらも履歴全体をメモリに持ちません。

画像の中身は画像 ID から決まる乱数で描くので、1 枚ごとに違います。同じ中身の画像をまとめても
小さくならず、履歴の大きさがそのまま保存の大きさになります。

## 規模

開発用の `Small()`（既定）と、本番の規模の暫定値 `Large()`（`go run . -scale large`）があります。
`Large()` はユーザー 5,000 人、履歴は 2026-10-27 までの 365 日で、投稿約 63 万件、RealMoji 約
121 万件、画像は合わせて約 14 GB です。履歴をアプリと DB のメモリより十分大きくし、すべてをメモリに載せる実装を
できなくするための規模で、値は較正で決めます。

### `Small()`

| 項目 | 値 |
|---|---|
| ユーザー | 1,000（リージョンは asia 99%、europe 0.5%、america 0.5%。サービスはアジアで広まっていて、海外にはまだ少ない） |
| 履歴 | 2026-09-29 までの 30 日。全リージョンが毎日 1 回ずつ投稿期間を開く（すべて終了済み） |
| 友達関係 | 約 5,000。優先的選択でべき分布にし、約 2 割はリージョンをまたぐ |
| 友達申請 | 成立した関係ごとに accepted を 1 件。ほかに pending 500、rejected 200、cancelled 100（重複を除くので少し減る） |
| 認定公開アカウント | 10 人（asia 8、europe 1、america 1）。通常ユーザーが 0〜5 件フォローし、上位ほど選ばれやすい |
| ブロック | 約 50 件。ブロック関係の 2 人には友達関係、フォロー、保留中の申請を作らない |
| 投稿 | 約 10,000。1 人 1 日 1 件まで。80% が on-time（開始から 120 秒以内）、1% は削除済み |
| RealMoji / コメント | 約 20,000 / 約 10,000。その日に投稿していて、投稿が見える人だけが付ける。友達を優先し、友達以外は公開の投稿なら全員から、友達の友達までの投稿なら友達の友達から選ぶ |
| 通知 | 約 30,000（投稿期間ごとに、そのリージョンの全ユーザーへ 1 件） |
| 画像 | 約 31,000 枚、約 30 MB。すべて中身の違う JPEG |

関係（友達、フォロー、ブロック）はすべて履歴の開始前にできあがっていて、履歴の期間中は変わりません。

## ユーザーの役割

| 役割 | 割合 | bench での扱い |
|---|---|---|
| `history` | 約 90%（認定公開アカウントを含む） | 読むだけで、書き込まない |
| `cohort` | 約 10% | ログインして書き込んでよい |

退会済みのユーザー（約 2%）は履歴の最終日のあとに退会したことにしているので、履歴には
普通に参加しています。

## 初期データの言語と名前

初期ユーザーは地域内の3言語から1つを選び、表示名、自己紹介、投稿のキャプション、地名、コメントに同じ言語を使います。
コメントは投稿先ではなく、コメントを書いたユーザーの言語になります。
言語はユーザーIDから決定するため、生成順や投稿の日付によって変わりません。

| 地域 | 言語 |
|---|---|
| asia | 日本語、中国語（簡体字）、韓国語 |
| europe | 英語、フランス語、ドイツ語 |
| america | 英語、スペイン語、ポルトガル語（ブラジル） |

表示名は各言語の一般的な人名と、架空の別名を半々に混ぜます。
各地域と言語の組でユーザーの生成順に交互に選び、人数が奇数なら人名が1人多くなります。
英語の人名候補はeuropeとamericaで分けています。
同じ表示名が再び選ばれたときだけ通し番号を付け、初期ユーザー全体で表示名が重複しないようにします。
ユーザー名にも対応する英数字表記と通し番号を使い、`[a-z0-9_.-]`の制約と一意性を保ちます。

架空の別名は20種類を各言語で用意しています。
これらの別名と翻訳はこのデータセット用の創作です。

既存の生成乱数列を消費してから独立した乱数列でプロフィールの文字列を置き換えるため、ユーザーの地域、関係、画像IDを変えません。
キャプション、コメント、地名の候補数も従来と同じにして、履歴の件数と日時を保っています。
`public.go`の地域を受け取らない関数は負荷走行中の新規データ用で、従来の候補を使います。
今回の地域別生成は初期データが対象です。

変更を反映するには初期SQLまたはAMIを再生成し、同じ版の`dataset`を使ったbenchと組み合わせてください。
