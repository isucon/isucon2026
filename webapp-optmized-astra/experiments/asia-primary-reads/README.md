# アプリ改善後のAsia主DB読み取りの再比較

3台同期は総合スコアが上がらず2台同期へ戻し、181,005点でPASSした。現在のアプリでは画像本文の処理枠と応答待ちを分離し、通知SQL・署名・画像保存なども改善済み。以前の負荷配分を前提に採用したAsiaの読み取り分散を再比較する。

最初はasiaReplicaReadsだけをfalseにし、Asiaの全読み取りを既存db1へ戻す。追加の物理レプリカは動かしたまま保持する。EU・USの地域内読み取りと、更新応答前の2台への同期反映は維持する。主DBのCPU増加と、Asiaの読み取り前確認・I/O負荷の減少を、同じseedと反復で比較する。

変更前の2台同期の結果は185,395点・184,915点、3台同期比較後の切り戻しは181,005点で、すべてPASS。配布物は変更せず、設定をPulumiと配備スクリプトから反映する。新しいAWSリソースは作らない。


Asiaレプリカを動かしたまま主DB読み取りへ変更した結果は176,830点PASS（20261028T203054Z-team10）、無再起動の反復174,401点PASS（20261028T203453Z-team10）。初回の主DB CPU平均は55.18%、Asiaは34.91%、AsiaのI/O待ちは18.12%だった。読み取り先の変更だけでは改善を確認できなかった。

次は既存の停止手順で、参照されていないAsia派生レプリカだけを停止して比較する。稼働プロセスが主DBを読むことを確認してから停止し、元のAMIデータと派生レプリカのデータは保持する。アプリの読み取り先、EU・USの同期反映、画像保存先は変えない。

停止候補のPulumi更新は成功したが、VMへの設定配布中にAWS認証が期限切れになり、レプリカ停止処理には到達していない。設定上はasiaReplicaEnabled=false、実機のAsiaレプリカは稼働中。再認証後に配備・検証を完了してから計測する。
