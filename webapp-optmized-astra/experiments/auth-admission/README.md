# 登録・ログインの受付枠を独立させる候補

認証の計測で、Asiaの遅い登録の受付待ち中央値892ms、ログイン1,134msを確認した。小さい一般更新128枠を登録・ログインと関係更新などが共有しているため、登録・ログインに独立した128枠を設ける。

対象はPOST /api/auth/registerとPOST /api/auth/loginで、本文サイズが判明していて64KiB以下の場合だけ。大きい本文やサイズ不明の本文は既存の重み付き枠を使う。画像64枠、一般更新128枠、管理更新4枠、SQL接続16、レプリカ確認8枠は維持する。認証の枠も応答前のレプリカ反映が完了するまで保持する。

受付待ちの改善がSQL接続待ちや他のAPIの遅延へ移る可能性があるため、同じ診断を有効にして実機比較する。診断用ログは調査後に無効にする。
