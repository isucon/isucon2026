# 初期履歴の事前読み込み

認証キャッシュは160,884 / 167,634点PASSで改善を確認できず無効化した。Go optimizedとの差が大きい初期履歴に対象を移す。本候補の比較基準は認証キャッシュなし176,708 / 169,952点PASS。

起動時に各地域の初期ユーザーの投稿・コメント・リアクションをREPEATABLE READで読み込む。UUIDは16バイトで保存し、ユーザー情報・画像データ・署名済み応答はこのキャッシュに含めない。履歴APIでは同一のSQL文で変更記録と現在のユーザー情報を読み、変更のない期間だけキャッシュから応答を組み立てる。通常の投稿・リアクション・コメントの3 SQLを、インデックスによる変更確認とユーザー取得の1 SQLへ置き換える。認証の接続引き継ぎは維持する。

020-initial-history.sqlのトリガーは投稿・コメント・リアクションの変更を所有者・日付単位で記録する。一度変更された日はSQLへ戻し、キャッシュの再取得は行わない。窓の日付・締切変更や明示的TRUNCATEでは全体世代を変更する。通常の窓の終了時刻は応答に使わないため無効化しない。変更記録は同じトランザクションで保存し、ロールバックも反映される。世代をトランザクションIDの大小から推測しない。

reset.sqlはトリガーを抑止するが、キャッシュにはinitial_data_boundary以前のレコードだけを保存し、resetが削除する新規レコードは含めない。導入前から存在する新規投稿や新規の反応がある日は、マイグレーションであらかじめ変更済みにする。変更記録はresetや再配備で消さない。ユーザーの復元・名前・画像・鍵・退会は毎回のSQLに反映される。投稿の変更は当該日のSQLへの退避で反映する。

実DBテストで通常SQLとのJSON一致、51件の番兵を含むページ送り、コメント・リアクション各50件、同時刻のID順、削除・置換済みの反応の除外、現在のユーザー情報、SQLへの退避、更新のロールバック、別所有者の更新、トリガーを抑止したresetと再起動を検証する。

初期履歴キャッシュはPulumi astraのruntime.initialHistoryEnabledで管理する。新規AWSリソースは使わない。書き込み専用プロセスは読み込まない。配備スクリプトはHTTPの起動完了を待つ。ヒット数とSQLへの退避数だけを記録する。エクスポートへの適用はこの候補に含めない。
