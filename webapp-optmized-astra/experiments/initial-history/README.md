# 初期履歴の事前読み込み

認証キャッシュは160,884 / 167,634点PASSで改善を確認できず無効化した。Go optimizedとの差が大きい初期履歴に対象を移す。本候補の比較基準は認証キャッシュなし176,708 / 169,952点PASS。

起動時に各地域の初期ユーザーの投稿・コメント・リアクションをREPEATABLE READで読み込む。UUIDは16バイトで保存し、ユーザー情報・画像データ・署名済み応答はこのキャッシュに含めない。履歴APIでは同一のSQL文で変更記録と現在のユーザー情報を読み、変更のない期間だけキャッシュから応答を組み立てる。通常の投稿・リアクション・コメントの3 SQLを、インデックスによる変更確認とユーザー取得の1 SQLへ置き換える。認証の接続引き継ぎは維持する。

020-initial-history.sqlのトリガーは投稿・コメント・リアクションの変更を所有者・日付単位で記録する。一度変更された日はSQLへ戻し、キャッシュの再取得は行わない。窓の日付・締切変更や明示的TRUNCATEでは全体世代を変更する。通常の窓の終了時刻は応答に使わないため無効化しない。変更記録は同じトランザクションで保存し、ロールバックも反映される。世代をトランザクションIDの大小から推測しない。

reset.sqlはトリガーを抑止するが、キャッシュにはinitial_data_boundary以前のレコードだけを保存し、resetが削除する新規レコードは含めない。導入前から存在する新規投稿や新規の反応がある日は、マイグレーションであらかじめ変更済みにする。変更記録はresetや再配備で消さない。ユーザーの復元・名前・画像・鍵・退会は毎回のSQLに反映される。投稿の変更は当該日のSQLへの退避で反映する。

実DBテストで通常SQLとのJSON一致、51件の番兵を含むページ送り、コメント・リアクション各50件、同時刻のID順、削除・置換済みの反応の除外、現在のユーザー情報、SQLへの退避、更新のロールバック、別所有者の更新、トリガーを抑止したresetと再起動を検証する。

初期履歴キャッシュはPulumi astraのruntime.initialHistoryEnabledで管理する。新規AWSリソースは使わない。書き込み専用プロセスは読み込まない。配備スクリプトはHTTPの起動完了を待つ。ヒット数とSQLへの退避数だけを記録する。エクスポートへの適用はこの候補に含めない。

## エクスポートへの適用候補

initialHistoryExportEnabledを追加する。起動時に初期投稿の画像参照も保持する。各エクスポートは現在のユーザーと初期メタデータの変更記録を確認し、実行中に追加された投稿だけを従来の画像参照SQLで読む。両者をposted_at・IDの順でマージして既存のファイル一括読み取りとZIPストリーミングへ渡す。初期投稿に画像参照の欠落・重複・SQL内の画像がある場合は全体をSQLへ戻す。キャッシュ対象外なら追加のDB接続を取得しない。

021-initial-export.sqlは初期投稿・初期画像参照の変更を同一トランザクションで記録する。新しい投稿・画像は毎回の差分SQLで読むためキャッシュを失効させない。コメント・リアクションはZIPの内容に含まれないため、この変更記録には追加しない。元の履歴用の変更記録と窓・TRUNCATEの全体世代は継続する。画像本体は既存ファイルのままで、新しい永続ストアは作らない。

実DBと実ファイルを使い、ZIPを展開してJSONと全画像を従来SQL版と比較する。55件の初期投稿、新しい投稿の混合順序、新しい本文・画像の更新、ユーザーの鍵変更、初期化での差分削除、初期画像の変更・削除・ID重複・TRUNCATE、ロールバックを検証する。現在の候補の性能は実機ベンチで判断する。

エクスポート拡張1611eebは20261030T084652Z-team12で165,969点PASS、再起動なしの20261030T085252Z-team12で155,910点PASS。初回のエクスポートはAsia 263、Europe 93、America 100回でキャッシュを使い、記録上の退避は0回だったが、総合得点は低下した。initialHistoryExportEnabledをfalseへ戻し、初期履歴だけを継続する。021の変更記録は再有効化時の整合性を保つため残す。コード・ZIP比較テスト・不採用結果を記録する。

## 履歴の接続待ちを分離する候補

エクスポート拡張は無効に戻し、memoryPoolConnections=4を試す。月・日履歴の認証と取得だけを別の接続プールへ移し、フィード・検索等の16接続と待ち行列を分ける。接続先・レプリカ・SQL・認証・公開地域の判定は変えず、履歴リクエスト内の接続引き継ぎを維持する。0なら通常プールをそのまま返す。書き込み専用プロセスには追加プールを作らない。実DBテストは通常プールの唯一の接続を占有し、別プールの1接続で認証と履歴取得が完了することを確認する。
