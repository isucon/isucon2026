# 推薦フィードの初期グラフと変更分

初期履歴だけの比較基準は179,090 / 179,890点PASS。接続プールの分離は総合点が下がったため、ともに0へ戻した。本候補のスコアは実機で測定する。

起動時にinitial_friendshipsを読み、推薦の共通友人数Mと接続数C（上限30）をRustで計算する。各リクエストはREPEATABLE READの読み取り専用トランザクションを開始し、022-initial-graph.sqlが記録した変更ペアの現在値を初期グラフへ適用する。同じスナップショットから投稿候補・現在のユーザー・公開範囲・両方向のブロック・投稿済み条件・友達の有効な反応数Eを取得する。10E+3M+C、投稿日時、IDで整列し、同じカーソルと51件の番兵を使う。

友達関係のINSERT/UPDATE/DELETEと変更記録は同一トランザクションで確定する。初期グラフの変更や通常のTRUNCATEは世代を更新し、既存キャッシュはSQLへ戻る。初期グラフ変更時は現在の辺との照合対象も記録する。初期化では既存のトリガー抑止下でfriendshipsを初期値に戻し、変更記録を同じトランザクションで空にする。キャッシュを再起動せず使い続けられる。TTLや非同期の無効化通知は使わない。

Pulumi astraのruntime.initialGraphEnabledで有効化し、書き込み専用プロセスではロードしない。新規AWSリソースは不要。022の導入とreset.sql更新はapply.sh upgradeで全アプリを停止して実施する。切り戻しはフラグをfalseにして通常配備する。

実DBテストは独立した既存の参照計算と比較する。疎・密な友達関係、複数ページ、Cの上限、重複した反応、退会、ブロック、地域と投稿窓、投稿削除を含む。さらに同じキャッシュのまま更新のロールバック・初期化・世代変更を確認する。候補SQLをテーブルロックで止めて友達関係を変更し、応答内で新旧の状態が混ざらず、次の要求には変更が反映されることを検証する。
