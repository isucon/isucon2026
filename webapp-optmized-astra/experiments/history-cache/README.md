# 所有者ごとの履歴・エクスポートメタデータキャッシュ

2026-10-30、実装cf0a9a59。ローカルの検証とリリースビルドは完了。Team 12への配備と候補版の性能測定は未実施で、改善幅はまだ確認できていない。

Memoriesは所有者の投稿・コメント・リアクションを初回にまとめて読み、月別・日別・ページ送りで再利用する。ヒット時は投稿・コメント・リアクションのSQLを、変更記録の照合と関係ユーザーの一括取得に置き換える。認証は従来どおりSQLで行い、ユーザーの有効性・表示名・プロフィール画像・署名鍵はキャッシュしない。

エクスポートは投稿と外部画像の参照キーをキャッシュする。ヒット時は画像テーブルのLATERAL JOINを省き、既存の画像キャッシュまたは不変ファイルを読む。画像本体がSQLに残る所有者は従来のSQL経路を使う。ZIPの同時実行2枠、画像読み取り完了後の200応答、直接ストリーミング出力は維持する。

018-history-cache.sqlが投稿・コメント・リアクション・画像の更新を、所有者とトランザクションIDの組として記録する。所有者ごとの共有カウンターを更新しないので、別トランザクション同士はその行をロックし合わない。照合にはコミット済み記録の件数を使う。トランザクションIDの最大値では、番号の小さいトランザクションが後からコミットした場合に変更を見落とすためである。

キャッシュの読み込みはREPEATABLE READで行い、レコードと変更記録を同じスナップショットから取得する。投稿期間の変更は全所有者を無効化する。initializeはトリガーを止めてデータを戻すため、reset.sqlで世代IDを同時に変更して変更記録をTRUNCATEする。これらの更新も既存の物理レプリケーションで配信され、既存の書き込み応答バリアを通る。

保持量の見積もり上限は履歴96MiB・エクスポートメタデータ32MiB、それぞれ最大2,048所有者。上限に達すると古い挿入順に退避し、単独で上限を超える結果は保持しない。処理中のリクエストが参照する退避済みデータや読み込み途中のデータは一時的に残る。履歴の読み込みは各プロセス最大4件に制限する。変更記録はinitializeごとに回収する。

検証はライブラリ39件成功・既存2件ignored、画像・署名・フィード・ログインの結合テスト7件成功、Clippy全ターゲット成功、releaseビルド成功。新しい実DBテストは旧SQL結果との一致、50件制限とページ送り、ユーザー更新・削除、コメント・リアクション・投稿・画像参照の変更、コミット順の逆転、ロールバック、初期化を確認する。詳細はvalidation.jsonと各txtに保存した。
