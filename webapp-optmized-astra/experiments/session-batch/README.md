# 接続待ちの認証要求を新しいSQLへまとめる

2e878071は、各HandlerContextに認証要求の処理キューを置く。1要求を受けてからメタデータDB接続を確保し、その間に届いた要求も最大128件までまとめて、現在の有効セッションとactiveユーザーを1つのSQLで照合する。意図的な待ち時間は設けない。重複トークンはSQLに1回だけ渡し、各要求へ個別に結果を返す。内部チャネルの容量は1,024件で、満杯のときは送信側が空きを待つ。

照合結果をバッチの外へ保存しない。SQL発行後に届いた要求は次のSQLへ回すため、後続要求がログアウト前の照合結果を共有することはない。地域は同じSQLで現在値を読む。主DBを使うコンテキストとレプリカを使うコンテキストは別のキューを持つ。DBエラーはそのバッチ全員にエラーとして返し、過去の認証結果へ戻さない。接続は結果を取り出した直後に返す。

[実装](../../rust/src/session_batch.rs)と[実DBテスト](../../rust/src/session_batch_tests.rs)。同時320要求で重複・異なるユーザー・無効トークンを混在させ、応答の対応を確認した。ログアウト、アカウント削除、地域変更、再有効化の後は次の照合から変更が反映される。DBテーブル消失時に失敗し、再作成後は同じトークンでも現在の対応へ変わることも確認した。

ライブラリ39件成功・既存2件ignored、ログイン・登録・画像・署名・フィード・検索の結合テスト9件成功、Clippy全ターゲット警告なし、releaseビルド成功。実DBテストはローカルPostgreSQLの独立スキーマを使用。配備後は3地域のバイナリ・runtime・保存先・レプリカを照合した。
