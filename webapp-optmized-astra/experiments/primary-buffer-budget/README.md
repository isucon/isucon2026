# プライマリの共有バッファ比較

メタデータ専用のdb1ではshared_buffersを512MiBに固定していた。画像をファイルへ移し、署名・通知・ログのアプリ処理を改善した後も、db1の負荷時には読み取り約10MB/s、I/O待ち約13〜16%が残る。現在の構成で1GiBと比較する。レプリカ側の512MiB設定は維持する。

`primarySharedBuffersMiB`をruntime.jsonとPulumiで管理する。`apply.sh database`がPostgreSQLの設定へ反映し、値が変わった場合だけプライマリを再起動する。`verify-runtime.py`は実際の設定をバイト数で照合する。ベンチの終了後に適用し、複製とアプリの接続を確認してから測定する。切り戻しも同じ配備手順で512へ戻す。

同じアプリでの512MiB対照は190,094点と177,132点でPASS。容量変更でコードや画像保存先は変えず、1024MiBを反復する。全体のメモリ余裕とI/O・スコアを併せて比較する。
