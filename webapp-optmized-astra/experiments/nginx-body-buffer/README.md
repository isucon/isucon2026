# リクエストバッファを保ったままアップロードの一時ファイルを減らす比較

リクエストバッファリングを無効にした比較は改善せず、現在は有効に戻している。今回の候補ではバッファリングを有効に保ち、client_body_buffer_sizeを256KiBへ増やす。32MiBのリクエスト上限は維持し、大きな本文は従来どおり一時ファイルへ退避できる。

[公式ドキュメント](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_body_buffer_size)によると、本文がメモリバッファを超えると全体または一部を一時ファイルへ書き込む。現在の64bit x86で既定の8KiBから増やし、小さな画像の書き込みを減らせるか比較する。並行アップロード中のメモリ使用量と実機スコアも確認する。実機の設定は測定前に確認する。

Pulumi runtimeのnginxClientBodyBufferKiBに容量を記録し、既存3アプリVMのNginxへ反映する。省略時は8KiB。実機比較は未実施。

ローカルでは生成スクリプトを256KiB・同値再適用・8KiBへの復帰の順に実行し、重複設定が増えないことと、リクエストバッファリングが有効のままであることを確認した。各段階のNginx構文検査、Pulumi型検査、Bash/Python構文検査は成功した。
