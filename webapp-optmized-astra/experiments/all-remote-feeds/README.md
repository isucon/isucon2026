# Asiaの通常フィードも既存USレプリカへ分散する

推薦だけに使っていた既存US読み取り専用32接続へ、public・friends・followingのSQLも送る。新しいAWSリソースやDB接続プールは作らない。Asia公開アプリだけが対象で、EU/USの地域内フィードとAsia認証は維持する。SQL、順位、公開範囲、ページ送りは同じ。

フィードはlogin_sessionsを参照しない。ログイン・ログアウトだけの主DB認証例外はフィードの可視性に影響せず、投稿・関係・ブロック・退会・地域変更は従来の全レプリカ反映待ちを維持する。remoteAllFeedsEnabledは既存の検証済み専用読み取り設定を必要とする。設定はPulumi astra、配布env、実プロセス照合へ反映する。

実DBテストでは通常プール3接続を全て保持し、独立した読み取り専用1接続で各通常フィードを取得できることを確認する。既存の独立参照計算で、公開範囲、友人・フォロー・ブロック、退会、投稿期間と地域、疎・密な関係、ページ送り、推薦順位の全ケースを比較した。通常経路と専用経路の両方が一致。Clippy全ターゲットとTypeScriptチェックも成功。

画像の利用者別配置は維持する。基準は200,330点PASS、同構成を再起動しない反復は188,075点PASS。次の候補は未測定。EUの空き容量が4.2 GiBなので配備前に既存GCで未参照画像を回収する。追加した利用者別配置はGC対象外の別ディレクトリにあり、元の月別パックはSQL参照により保持される。
