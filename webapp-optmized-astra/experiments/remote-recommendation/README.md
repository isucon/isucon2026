# Asiaの推薦集計を既存USレプリカへ送る

セッション用の専用接続ではログインp90を55.5msまで短縮したが、推薦フィードp90が929.6msとなり、総合は173,130点PASSだった。通常の要求と履歴の処理が主DBのCPUを取り合っている。直近の初期履歴＋認証先固定の測定では、主DBはCPU平均70.8%、p95 100%、US VMは平均28.2%だった。VMの型と時刻は異なり、CPU余力だけで改善を予測しない。

recommendationReadRegion=americaを指定すると、Asiaの公開アプリだけが既存US PostgreSQLレプリカに読み取り専用で接続する。friends-of-friendsの推薦SQLだけをこのプールへ送る。認証、ほかのフィード、検索、履歴、書き込みの接続先は維持する。SQL・スコア・公開範囲・カーソルは同じ。既存の通常変更はUSを含むnative remote_applyバリアで保護される。ログイン・ログアウトの例外については認証を従来のAsia主DBで済ませ、推薦SQLはセッションを再検証しない。

32接続を受け付け開始前に確立する。接続先が指定の物理レプリカであることをpg_is_in_recoveryとprimary_slot_nameで確認する。要求ごとの余分な接続確認pingはせず、切れた接続でSQLが失敗した場合はその要求を失敗として扱う。処理途中のSQLは再試行しない。地域間RTTを追加するため、主DB負荷の削減と応答時間の両方を実機で評価する。

設定はPulumi astra、logging-runtime.sh、verify-runtime.pyに反映する。空文字なら元の接続を使う。新しいAWSリソース・DB・API・秘密値は作らない。Asiaから既存のアプリ用資格情報でUSレプリカへ接続できることを確認した。

実DBテストでは通常の3接続をすべて占有し、別の1接続で推薦を取得する。SQL版と初期グラフ版の両方を独立した参照計算と比較し、疎・密な関係、複数ページ、反応、ブロック、退会、地域と投稿期間の変更を確認する。初期グラフ版は実機では無効のまま。セッション専用8接続と認証先固定は前候補から維持する。本候補のスコアは未測定。
