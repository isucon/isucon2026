# Asiaのセッション認証を主DBへ固定する

Go版との調査は../optimized-gap/README.mdを参照。初期履歴を読む各ループにもログインが入り、RustのAsiaログインは中央値268.5ms、Go Team 9の既存走行は7.9msだった。初期履歴だけの採用構成は179,090 / 179,890点PASS。推薦グラフ候補は164,125点PASSで無効化済み。本候補の性能は実機で測定する。

023-session-authority.sqlはusers.auth_home_regionを追加する。既存ユーザーは初期スナップショットのregion（なければ現在値）、新規ユーザーは登録時のregionを使う。INSERTのトリガーが値を設定し、UPDATEでは元の値を維持する。表示上のregion変更や初期化では認証先を変えない。

Asiaを認証先とする利用者のセッションは、どの地域からでも主DBで検証する。海外のローカルSQLはこの利用者を除外し、見つからないトークンは主DBへ問い合わせる。新規トークンがまだレプリカに存在しない場合も正しく扱い、古いトークンがレプリカでactiveのままでも信用しない。他の利用者の認証は既存のローカルSQLを維持する。主DBに接続できない場合に古い認証結果へ戻ることはない。

成功したlogin/logoutだけ、応答の利用者IDから変更されない認証先を主DBで確認し、Asiaなら通常のローカル永続コミット後に返す。レプリケーション自体は継続する。対象外のセッション、投稿・プロフィール・退会などの変更、認証先の確認に失敗した場合は従来の反映待ちを維持する。セッションキャッシュとの同時有効化は禁止する。

primaryAsiaSessionsEnabledは認証経路、localAsiaSessionWritesEnabledは早い応答を個別に制御する。後者をfalseへ戻すだけなら通常配備で切り戻せる。認証経路を変更する際はapply.sh upgradeが必須。全アプリを停止し、DBマイグレーション後にremote_applyのバリアを確定させてから全アプリを再開する。旧アプリの未反映セッションと新しいスキーマの両方を確認する。runtime、環境変数、Pulumi検証、配備後検証へ反映する。新規AWSリソースや秘密情報の保存先は追加しない。

実DBと2レプリカの結合テストで、片方のWAL再生を停止する。ログアウトが完了してもレプリカではactiveの旧トークンを拒否すること、未反映の新規トークンが使えること、同時ログインのうち最後だけが有効であること、地域変更・退会・新規登録を確認する。主DBプールを全て占有しても対象外ユーザーの認証はローカルSQLで完了する。通常の書き込みと対象外のログインは再生再開まで応答しないことも検証する。

## 初回測定

fc1737d8、20261030T101825Z-team12、固定seed 1で192,515点PASS。Asiaログインp50は268.5→41.2ms、p90は2,005.7→1,316.2ms、ログアウトp50は301.9→36.6ms。月履歴は3,180→5,341件、日別履歴は703→1,455件へ増加した。月履歴p50は80.0→23.0ms、日別73.6→10.2ms。比較元は初期履歴のみの20261030T083137Z-team12。実行時刻、事前の画像GC、署名ファイルの更新などの条件差が残る。構成を維持して反復測定し、残る認証と通常読み取りの接続待ちを調べる。

再起動・設定変更なしの20261030T102348Z-team12は170,867点PASS。Asiaログインp50は18.1ms、月履歴は10.3msと短くなった一方、推薦フィードp90は643.4ms、Asiaの負荷ユーザーは947→636人となった。初回192,515点だけを安定した総合改善とは扱わない。認証の反映待ちを削減できたことと、通常の負荷の成長を維持できたかは分けて評価する。

## セッション用の接続を分離する候補

sessionPoolConnections=8を追加する。ログイン・ログアウトの認証と更新、および主DBでのセッション確認・認証先確認を専用プールへ移す。接続先とSQLは同じで、0なら従来のプールを共有する。履歴と短い読み取りの専用プールはまだ0のまま。通常の主DBプールを全て占有しても、専用プールの1接続でログイン・ログアウトが完了することを実DBで検証する。既存のWAL再生停止テストも専用プールを使って続ける。

専用8接続43412d6、20261030T103602Z-team12は173,130点PASS。Asiaログインp50/p90は12.8/55.5ms、ログアウト11.2/35.0msへ短縮したが、推薦フィードは345.5/929.6ms、負荷ユーザー数は510人となり、総合改善は確認できなかった。月履歴は5,712件。次は主DBに集中する推薦集計を既存USレプリカへ移す候補を調べる。専用接続は比較用に維持するが、採用確定とはしない。
