# ファイル保存後のアップロードバッファ比較

従来の画像SQL保存時にはNginxのリクエストバッファ無効化でスコア改善を確認できなかった。現在は画像を各地域のファイルへ保存しているため、Nginxの一時ファイルへの保存とアプリの永続化が重なるI/Oを再比較する。

既存の`nginxRequestBuffering`だけをfalseへ変更する。上流HTTP/1.1と接続再利用は全地域で有効。本文の検証、画像保存のfsync、公開前のメタデータ確定、複製反映確認、アプリの実行枠は維持する。直前の通知バッチ構成は169,421点・174,707点・187,187点でPASSしている。

初回は156,485点でPASS。負荷開始後60秒のAsia平均ディスク書き込みは22.94MB/sで、直前のバッファ有効走行35.14MB/sより少なかったが、要求数も異なる。投稿p90はAsia 3,696ms、Europe 5,675ms、America 5,952msとなり、対照の3,538ms、4,698ms、5,246msを下回らなかった。反復は非JPEGプロフィール画像の400応答がタイムアウトし、準備段階で0点FAILだった。原因は未確定。改善を確認できていないためtrueへ戻して対照を測定する。
