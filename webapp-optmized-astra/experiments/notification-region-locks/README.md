# 通知対象の確定時に取るロックの範囲

実機の待ち関係を採取し、通知の一括INSERTが保持するusersテーブルのSHAREロックにより、登録・プロフィール画像更新が待つことを確認した。別の走行では登録最大0.929秒、bio更新最大0.793秒の待ちを観測した。

地域の投稿期間を開く処理は、その地域のadvisory exclusive lockを保持する。usersの登録・地域変更・状態変更・削除はトリガーで対象地域のshared lockを取る。地域変更は移動前後の2地域を順に取る。これにより通知対象を確定する間も、プロフィール編集や別地域の登録は進められる。

結合テストは通知対象・重複開始・失敗時の原子性を既存どおり確認し、Asiaの開始を止めた状態で、Asiaへの登録・地域変更・再有効化が待ち、bio変更・Europeへの登録が完了することを確認する。

配備はベンチ停止中に`apply.sh upgrade`を実行する。稼働中の設定を事前確認してから全アプリを停止し、016を適用して新しいアプリを起動する。旧アプリのテーブルロックと新しいトリガーを併用する期間に更新要求を流さない。ロールバック時もアプリを停止し、トリガーを外してから旧アプリに戻す。
